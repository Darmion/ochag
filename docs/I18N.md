# Interface translation

Ochag ships with Russian and English and loads further languages from files that users add themselves, without rebuilding the app. English is the default.

## Keys are the Russian text

A string's key is the Russian text itself, as in gettext: the code calls `t('Сохранить')`, and the English dictionary holds `"Сохранить": "Save"`. There are no invented key names, the code stays readable, and a missing translation shows the Russian original.

| Where | What |
|---|---|
| `apps/client/src/i18n/i18n.ts` | `t(key, params)`, `tn(count, key)`, `tr(key)`, the current language `locale`, the language list and user languages |
| `apps/client/src/i18n/i18nCore.ts` | the Vue-free logic. It is a copy of `packages/domain/i18n/i18n.ts`, because the client does not import packages; a test keeps the copies identical |
| `apps/client/src/locales/en.json` | the built-in English: every interface string, grouped by the file it comes from |
| `apps/client/src/locales/keys.ts` | the strings passed to `t()`, `tr()` and `tn()`; generated by `npm run i18n:extract` |
| `apps/client/src/locales/srd-en.json` | the official English names and texts of the SRD 5.1 (spells, monsters, weapons, items, feats); loaded separately when the language is not Russian |
| `scripts/i18n-strings.mjs` | collects the strings and merges them into `en.json` |
| `%APPDATA%\ttrpg-foundation\locales\*.json` | the user's own languages |

- `t('Версия {version}', { version })` substitutes `{name}` placeholders; `{{` and `}}` are literal braces.
- `tn(count, '{n} кость|{n} кости|{n} костей')` handles plurals: the key holds the three Russian forms separated by `|`, and a translation is an object of forms by the rules of its language (`Intl.PluralRules`), for example `{"one": "{n} die", "other": "{n} dice"}`.
- `tr('…')` marks a string inside data, such as tab or list labels, so that the extractor finds it. It returns the text unchanged; `t(entry.label)` translates it when shown.
- **Language chain:** the chosen language, then its `base` (English by default), then the Russian original. A language with ten translated strings shows those ten and English for the rest.
- The language is a per-computer setting (Settings → Language). It changes at once, without a restart, and sets `<html lang>`.

## The English file

```json
{
  "$meta": { "code": "en", "name": "English", "base": null },
  "$about": ["…notes for translators…"],
  "Общие — встречаются в нескольких файлах": { "Сохранить": "Save" },
  "components/sheet/CharacterSheet.vue": { "Хиты: {hp} из {hpMax}": "HP: {hp} of {hpMax}" },
  "Больше нет в коде — перевод сохранён, чтобы не пропал": { "…": "…" }
}
```

- The left side is the Russian key and must not change; the right side is the translation. An empty value means not yet translated, and the interface shows the Russian text.
- **Sections** are the files a string comes from; strings used in several files go to the shared section («Общие…»). Sections do not affect translation: the same text is translated once. User language files may use sections too.
- **Placeholders** come from the code: `{{ character.hp }}` in a template becomes `{hp}`, `` `${name} …` `` becomes `{name}`, and `'Хиты: ' + hp` becomes `Хиты: {hp}`; without a clear name the placeholder is `{value}`. Keep placeholders unchanged in translations.
- **Where strings come from.** The extractor reads `apps/client/src`, `apps/server/src`, `apps/desktop`, `packages/domain`, `packages/importer` and `mods`: template text and static attributes (`title`, `placeholder`, `aria-label` and others), string and template literals in code, and the captions of the picture libraries. It skips comparisons and text searches (`=== 'Воин'`, `.includes(…)`), `console` calls, regular expressions, object keys, types, `itemArt.ts` (word stems for matching pictures) and the `example` and `higher` properties of `spell-template-rules.ts`, which are Russian samples the spell parser learns from.
- **Merging** (`npm run i18n:extract`) adds new strings with empty values to their sections and never touches existing translations. A translated string that is gone from the code moves to the «Больше нет в коде…» section so that its translation is not lost; an untranslated one is dropped.

## Translating the page

Components write Russian text, and the server sends errors and log entries in Russian. The client translates the page itself with the same `en.json`:

| Where | What |
|---|---|
| `apps/client/src/i18n/domTranslateCore.ts` | the translator, without the DOM; tested in `apps/client/test/i18n/dom-translate.test.ts` |
| `apps/client/src/i18n/domTranslate.ts` | walks the page and watches it with a `MutationObserver`: text nodes and the `title`, `placeholder`, `aria-label`, `alt` and `label` attributes |

The translator tries, in order:

1. **An exact match** of the string, after collapsing whitespace.
2. **Patterns.** A key with `{name}` becomes a regular expression, and the Russian value of a placeholder («Свет», «отравлен») is translated with the same dictionary, to a limited depth. Of several matching patterns the one that leaves the fewest Russian letters wins; on a tie, the one with more fixed text. Adjacent placeholders (`{name}{value}`) are not translated, because the boundary between them is unknown.
3. **Edges.** Icons, brackets, quotes and a trailing colon are trimmed step by step and kept as they were («☀ День 1», «(Вы)»); half of a quote or bracket pair is never trimmed.
4. **Composite strings.** Parts joined by « · », « → », « — », «: », «; » or «, », and a note in brackets at the end, are translated part by part when that leaves less Russian. A split at the first separator is tried too, because the text after a name is often a whole key of its own («Лира — Клетка занята… — встаньте рядом.»). Last, Russian words between numbers, dice and Latin text are translated one by one («1d8+@mod рубящий», «8 зм 5 см 7 мм»). The case of the first letter follows the source.

Other rules:

- **Not translated:** `script`, `style`, `code`, `pre`, the contents of input fields (their placeholders are translated), and everything marked `translate="no"` or `.notranslate`. Text people write, such as chat, notes, quests and handouts, is marked this way.
- **Names:** `protectNames(group, names)` protects the names of creatures and scenes on the table, campaigns and the party, even when a name matches a dictionary word («Жертва», «Торговец»). A name taken straight from the SRD («Гоблин») is translated.
- **Quotes:** in English, a text node that holds only quotes next to an untranslated name (`«<span translate="no">…</span>» — …`) gets English quotes, like its neighbours.
- **SRD texts** are shown in the official English where it exists, instead of a translation of the Russian retelling: the compendium, the bestiary and the beast choice for summons take SRD names and descriptions as they are, and skills have `descEn` in `packages/domain/srd/skills.json`.
- Choosing Russian removes the layer and restores the original text.
- `shownText(text)` returns a string as the layer would show it. The table search (Ctrl+K) uses it to search the shown text as well as the Russian original.

## Text outside the page

- **Window title.** The observer watches `body` only, so code that sets `document.title` translates it with `shownText`.
- **Windows' own dialogs.** Titles of the file dialogs, file type names, the default file name and the startup error box are not part of the page. The page translates the list in `apps/client/src/i18n/nativeTexts.ts` and sends the result to the main process over the `locales:nativeTexts` channel. `apps/desktop/main/native-texts.cjs` keeps it in `native-texts.json` in the data folder, so the next start's error box uses the last language, and `nativeText('…')` looks a text up. A test checks that every `nativeText('…')` in the main process is in that list, and that the list has no unused texts.

## Adding a language

1. Settings → Language → **Save a translation template**. The languages folder gets `template.json`: every interface string in the same sections as `en.json`, with the Russian text as the key and the English as a sample.
2. Copy it to a file named after the language code (`de.json`, `fr.json`, `pt-BR.json`), fix `$meta` and translate the values:

   ```json
   {
     "$meta": { "code": "de", "name": "Deutsch", "base": "en" },
     "Стол": "Tisch",
     "Отряд": "Gruppe",
     "{n} кость|{n} кости|{n} костей": { "one": "{n} Würfel", "other": "{n} Würfel" }
   }
   ```

   Do not translate the keys or the `{placeholders}` inside the strings.
3. Click **Refresh list**. The language appears in the list with its completion percentage; problems in the file, such as a non-string value or a bad language code, are shown below the buttons.
4. The file can be shared: another player puts it into their own languages folder.

Untranslated strings come from the `base`: `"base": "en"` takes them from English, `"base": null` from Russian. A language file may be up to 5 MB and 50,000 strings.

## Writing translatable code

- Text for people goes through `t()` in templates (`{{ t('…') }}`, `:title="t('…')"`) and in code; in data use `tr()`, and `t(entry.label)` when showing it. Plain Russian text in a component is translated by the page layer as long as `en.json` has it.
- **Write whole phrases with placeholders**, never concatenations: `t('Версия {version}', …)`, not `'Версия ' + version`, because word order differs between languages.
- **Do not inflect names:** names are not declined in any language.
- Use `tn()` for plurals, not `n === 1 ? … : …`.
- A text that the main process shows in a Windows dialog goes through `nativeText('…')` and into `NATIVE_TEXTS`.
- After changing text, run `npm run i18n:extract`. It updates `keys.ts`, adds new strings to `en.json` with empty values and lists the `t()` strings that have no English. Fill the empty values; never overwrite a translation someone else wrote. `packages/domain/i18n/i18n.test.ts` fails when `keys.ts` is out of date or a `t()` string has no English, and `npm run i18n:check` fails while any string in `en.json` has no English. The GitHub checks run both.

## Limitations

- English and other languages run longer than Russian; tight places such as the action bar need checking in each language.
- The bundled fonts cover Latin and Cyrillic. Chinese, Japanese and Korean need their own fallback font.
- Right-to-left scripts are not supported.
- Texts that people write (names, notes, custom spells) and texts mods produce at run time are not translated.
